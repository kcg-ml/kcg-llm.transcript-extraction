## NOTES

- The photo stage runs on `zai.glm-5.3-flash-128k` (`glm-5.3-flash`, accepts
  `text` and `image`). `pi auth check --provider zai` prints `not_ready`
  `credentials_not_configured`, but the key file `~/.config/opencode/keys/zai.key`
  named in `models.json` answers HTTP 200 on `https://api.z.ai/api/coding/paas/v4`.
  Trust the call, not the auth check. Run the job with
  `--provider zai.glm-5.3-flash-128k --model glm-5.3-flash`.
- The `zai` content filter refuses 1 photo of the 797 with HTTP 400 `code 1301`
  at full size and passes it at 200 px. `internal/durablejob` retries a photo
  once at 200 px through `sips` and writes the copy to `model-answer/shrunk-photo/`.
- A photo prompt that does not name the answer language gets Chinese or Russian
  field labels, and `internal/phototable` then parses no field. The prompt now
  states `Write every value in English`. 21 of 797 answers had to be re-run.
- The rollup prompts `prompts/summary-window-of-whole-chat-*.txt` reach the runner only through
  `data/windows.csv`. `internal/summaryaggregation` appends them there, so run
  `transcriptextraction aggregate` before
  `transcriptextraction job --job summary-window-of-whole-chat`.
- `transcriptextraction aggregate` rewrites `data/index.csv` and drops the photo
  rows, so run `transcriptextraction photo-index` after it.
  `transcriptextraction pipeline` already does this.

- The model name `deepseek-v4.1-flash-1017` matches 9 authenticated providers.
  `pi` then prints `Error: Model ... is ambiguous` on stdout and exits 0, so a
  runner that trusts the exit code saves the error as an answer. `internal/durablejob`
  names the provider `local-dgx1.deepseek-v4.1-flash-1017-128k` and treats an
  `Error:` first line as a failure.
- A model call can outlive its timeout when a child holds the pipe open.
  `internal/durablejob` kills the process on timeout instead of waiting.
